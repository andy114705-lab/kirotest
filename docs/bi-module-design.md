# 邮轮行业 BI 数据分析模块 — 产品设计方案

> 版本: v1.0 | 日期: 2026-05-12
> 范围: 数据域一(收益与预订) + 数据域二(船上消费) + 数据域三(旅客画像)
> 使用者: A.船公司高管/运营总监  B.收益管理/市场销售团队
> 分析模式: 按航次统计, T+1 经营分析为主

---

## 一、产品定位与设计原则

### 1.1 产品定位

| 项目 | 说明 |
|------|------|
| 形态 | 现有系统内独立 BI 模块（非独立系统） |
| 数据源 | 跨 CRS/PMS/PSS 汇聚, 支持客户仅部署单一系统的降级展示 |
| 分析粒度 | 以"航次"为核心维度, 支持下钻至舱型/渠道/旅客 |
| 时效 | T+1 批量分析为主 |
| 多租户 | 单船公司部署, 数据物理隔离 |
| 币种 | 单一主币种(人民币/美金), 系统级配置 |

### 1.2 设计原则

1. **数据源可选**: 客户可能只用 CRS, 未装 PMS 时船上消费看板自动隐藏
2. **航次为轴**: 所有核心指标围绕航次聚合, 支持航次对比
3. **角色分层**: 高管看"一页纸"摘要, 收益经理看详细下钻
4. **渐进增强**: MVP 先用视图/物化视图, 后续再引入数据仓库
5. **包船/团队/MICE 标签化**: 航次、订单打标签, 支持按业务类型切片

## 二、数据模型核心实体关系

```
航季(Season)
  └── 航次(Voyage/Sailing)
        ├── 舱房(Cabin) ── 舱型(Category)
        ├── 订单(Booking)
        │     ├── 旅客(Passenger)
        │     ├── 渠道(Channel)
        │     └── 订单标签(Tag: 散客/包船/团队/MICE)
        └── 船上消费(OBR Transaction)
              ├── 消费业态(Revenue Center)
              └── 套餐(Package)
```

### 关键主数据(已具备)
- 旅客ID (跨系统统一)
- 航次ID (跨系统统一)
- 舱房ID (跨系统统一)

### 需要补充的维度表
- 渠道维度表 (直销/OTA/旅行社/包船方)
- 业态维度表 (餐饮/酒吧/SPA/免税/岸游/赌场/Wi-Fi...)
- 订单业务类型 (散客/包船/团队/MICE)
- 旅客标签 (首航/回头客, 会员等级, 家庭结构)

## 三、数据域一 — 收益与预订分析 (数据源: CRS)

> 这是 MVP 的第一优先级, 高管和收益经理每天必看。

### 3.1 核心指标清单

| # | 指标名称 | 英文 | 计算口径 | 分析维度 | 角色 |
|---|---------|------|---------|---------|------|
| 1 | 总载客率 | Occupancy Rate | 已售床位 / 可售床位 × 100% | 航次, 舱型, 甲板 | A+B |
| 2 | 双人入住率 | Double Occupancy Rate | 实际旅客数 / 已售舱房数 | 航次, 舱型 | B |
| 3 | 预订进度曲线 | Booking Pace Curve | 按"离航日倒推天数"统计累计预订量 | 航次, 舱型 | B |
| 4 | 预订同期对比 | YoY / Voyage-over-Voyage | 当前航次 vs 去年同期/同航线航次 Pace | 航线, 航季 | A+B |
| 5 | 净票务收入 | Net Ticket Revenue | 总票款 - 佣金 - 退款 - 税费 | 航次, 渠道, 舱型 | A |
| 6 | 人均票价 | Average Ticket Price (ATP) | 净票务收入 / 旅客人数 | 航次, 舱型, 渠道 | B |
| 7 | 每可售床位日收入 | RevPBD (Revenue per Berth Day) | 净票务收入 / (可售床位 × 航程天数) | 航次, 船 | A |
| 8 | 渠道占比 | Channel Mix | 各渠道订单数/收入 占比 | 航次, 航季 | B |
| 9 | 渠道获客成本 | CAC per Channel | 渠道佣金+营销费 / 该渠道新客数 | 渠道, 航季 | B |
| 10 | 取消率 | Cancellation Rate | 取消订单数 / 总订单数 × 100% | 航次, 提前天数段, 原因 | B |
| 11 | 包船/团队/MICE 占比 | Group Ratio | 包船+团队+MICE 旅客数 / 总旅客数 | 航次, 航季 | A+B |
| 12 | 包船贡献收入 | Charter Revenue | 包船合同收入(含保底+分成) | 航次, 包船方 | A |
| 13 | 提前预订天数分布 | Lead Time Distribution | 下单日到出发日的天数分布 | 航次, 舱型, 渠道 | B |
| 14 | 舱型升级/降级量 | Upgrade/Downgrade Count | 航次内变更舱型的旅客数 | 航次, 原舱→新舱 | B |

## 四、数据域二 — 船上消费与辅助收入 (数据源: PMS + POS)

> 依赖 PMS 部署。若客户未装 PMS, 此模块自动隐藏。

### 4.1 核心指标清单

| # | 指标名称 | 英文 | 计算口径 | 分析维度 | 角色 |
|---|---------|------|---------|---------|------|
| 1 | 人均船上消费 | SPPD (Spend per Passenger Day) | 船上消费总额 / (旅客数 × 航程天数) | 航次, 业态, 旅客标签 | A |
| 2 | 船上消费总额 | Total OBR | 所有非票务收入合计 | 航次 | A |
| 3 | 业态收入占比 | Revenue Center Mix | 各业态收入 / 总OBR × 100% | 航次, 航季 | A+B |
| 4 | 套餐渗透率 | Package Penetration | 购买套餐旅客数 / 总旅客数 | 套餐类型, 航次 | B |
| 5 | 套餐升级率 | Package Upgrade Rate | 船上升级套餐的旅客数 / 已购套餐旅客数 | 套餐类型 | B |
| 6 | 岸上观光购买率 | Shorex Attach Rate | 购买岸游旅客数 / 总旅客数 | 港口, 航次 | B |
| 7 | 岸上观光人均消费 | Shorex ARPU | 岸游总收入 / 购买岸游旅客数 | 港口, 产品 | B |
| 8 | 消费时段分布 | Hourly Spend Pattern | 按小时/天统计消费金额 | 业态, 航行日vs靠港日 | B |
| 9 | 高消费旅客占比 | Top Spender Ratio | Top 20% 旅客贡献的 OBR 占比 | 航次, 旅客标签 | B |
| 10 | 免税品热销 TOP | Retail Top SKU | 免税店销售额排名前N的商品 | 航次, 品类 | B |
| 11 | 交叉购买率 | Cross-Sell Rate | 同时购买 ≥2 个业态的旅客占比 | 业态组合, 航次 | B |
| 12 | 包船旅客 vs 散客消费对比 | Charter vs FIT SPPD | 分组计算人均消费差异 | 航次, 业务类型 | A+B |

## 五、数据域三 — 旅客画像与 CRM (数据源: CRS + PSS + 会员系统)

| 1 | 旅客总量 | Total Passengers | 去重后的旅客人数 | 航季, 航次 | A |
| 2 | 新客占比 | New Guest Ratio | 首次航行旅客 / 总旅客 × 100% | 航次, 渠道 | A+B |

| 12 | 投诉处理时效 | Complaint Resolution Time | 从提交到关闭的平均小时数 | 类型, 航次 | B |
| 13 | RFM 分层 | RFM Segmentation | Recency×Frequency×Monetary 分桶 | 全量旅客 | B |
| 14 | 包船/MICE 客户留存 | Group Retention | 包船方/企业客户次年复购比例 | 客户, 年度 | A+B |

## 六、数据源适配策略 (客户仅部署部分系统)

> 核心设计: 模块化数据源, 按客户部署情况自动显隐看板。

| 客户部署情况 | 可用看板 | 降级说明 |
|---|---|---|
| 仅 CRS | 收益与预订(完整) + 旅客画像(部分: 无船上消费数据, 无NPS) | SPPD/OBR 看板隐藏, LTV仅含票务收入 |
| CRS + PMS | 收益与预订(完整) + 船上消费(完整) + 旅客画像(含LTV完整) | - |
| CRS + PSS | 收益与预订(完整) + 旅客画像(含NPS/投诉) | 船上消费看板隐藏 |
| CRS + PMS + PSS | 全部看板(完整) | 最佳体验 |
| 仅 PMS | 船上消费(完整) + 旅客画像(仅船上部分) | 无预订数据, 无Booking Pace |

### 实现方式
```
系统配置表: bi_data_source_config
┌──────────────┬─────────┬───────────┐
│ source_system │ enabled │ sync_mode │
├──────────────┼─────────┼───────────┤
│ CRS          │ true    │ T+1 batch │
│ PMS          │ false   │ -         │
│ PSS          │ true    │ T+1 batch │
└──────────────┴─────────┴───────────┘

前端根据 enabled 状态动态渲染菜单与看板组件。
```

```
│   │  │ 预订汇总  │ │ 消费汇总  │ │ 旅客汇总  │   │            │
│   │  │ (航次粒度)│ │(航次粒度) │ │(旅客粒度) │   │            │
│   │  └──────────┘ └──────────┘ └──────────┘   │            │

│   └──────────┘  └──────────┘  └──────────┘                 │
└─────────────────────────────────────────────────────────────┘
```

### 7.2 关键技术选型建议

| 层级 | MVP 方案 | 后续升级方向 |
|------|---------|------------|
| 前端图表 | ECharts / AntV (G2Plot) | 同 |
| API 层 | 现有后端框架(Java/Node) + BI 专用 Controller | 独立微服务 |
| 数据聚合 | 数据库物化视图 + 定时任务(Cron/xxl-job) | 引入 ClickHouse/StarRocks |
| 数据存储 | 在业务库中建 `bi_` 前缀汇总表 | 独立分析库 / 数据仓库 |
| 缓存 | Redis 缓存热门查询结果(TTL=1天) | 同 |
| 导出 | 后端生成 Excel (Apache POI / EasyExcel) | 同 |
| 定时调度 | xxl-job / Spring Schedule | Airflow / DolphinScheduler |

### 7.3 数据流 (T+1 ETL 流程)

```
每日凌晨 02:00 执行:

1. [抽取] 从 CRS/PMS/PSS 业务表拉取前一天变更数据 (增量)
2. [清洗] 统一ID关联, 币种确认, 空值处理, 业务类型打标
3. [聚合] 计算各指标, 写入汇总表:
   - bi_voyage_booking_summary    (航次预订汇总)
   - bi_voyage_obr_summary        (航次船上消费汇总)
   - bi_passenger_profile         (旅客画像宽表)
   - bi_channel_performance       (渠道表现)
   - bi_package_performance       (套餐表现)
4. [刷新] 更新物化视图, 清除 Redis 缓存
5. [标记] 写入 bi_etl_log (执行状态, 数据截止时间)
```

## 八、核心汇总表设计 (概要)

### 8.1 bi_voyage_booking_summary (航次预订汇总)

```sql
CREATE TABLE bi_voyage_booking_summary (
    id                  BIGINT PRIMARY KEY,
    voyage_id           VARCHAR(32) NOT NULL,     -- 航次ID
    stat_date           DATE NOT NULL,            -- 统计日期
    -- 舱位
    total_berths        INT,                      -- 总可售床位
    sold_berths         INT,                      -- 已售床位
    occupancy_rate      DECIMAL(5,2),             -- 载客率%
    -- 收入
    gross_revenue       DECIMAL(15,2),            -- 毛收入
    net_revenue         DECIMAL(15,2),            -- 净收入
    avg_ticket_price    DECIMAL(10,2),            -- 人均票价
    rev_per_berth_day   DECIMAL(10,2),            -- RevPBD
    -- 渠道
    direct_pax          INT,                      -- 直销旅客数
    ota_pax             INT,                      -- OTA旅客数
    agent_pax           INT,                      -- 旅行社旅客数
    charter_pax         INT,                      -- 包船旅客数
    mice_pax            INT,                      -- MICE旅客数
    -- 取消
    cancel_count        INT,                      -- 取消订单数
    cancel_rate         DECIMAL(5,2),             -- 取消率%
    -- 元数据
    data_source         VARCHAR(16),              -- CRS
    etl_time            TIMESTAMP,                -- ETL执行时间
    INDEX idx_voyage (voyage_id, stat_date)
);
```

### 8.2 bi_voyage_obr_summary (航次船上消费汇总)

```sql
CREATE TABLE bi_voyage_obr_summary (
    id                  BIGINT PRIMARY KEY,
    voyage_id           VARCHAR(32) NOT NULL,
    revenue_center      VARCHAR(32) NOT NULL,     -- 业态: F&B/BAR/SPA/RETAIL/SHOREX/CASINO/WIFI
    stat_date           DATE NOT NULL,
    -- 消费
    total_amount        DECIMAL(15,2),            -- 总消费金额
    transaction_count   INT,                      -- 交易笔数
    unique_guests       INT,                      -- 消费人数(去重)
    sppd                DECIMAL(10,2),            -- 人均日消费
    -- 套餐
    package_sold        INT,                      -- 套餐销售数
    package_revenue     DECIMAL(15,2),            -- 套餐收入
    -- 元数据
    data_source         VARCHAR(16),              -- PMS
    etl_time            TIMESTAMP,
    INDEX idx_voyage_center (voyage_id, revenue_center, stat_date)
);
```

### 8.3 bi_passenger_profile (旅客画像宽表)

```sql
CREATE TABLE bi_passenger_profile (
    passenger_id        VARCHAR(32) PRIMARY KEY,  -- 统一旅客ID
    -- 基本信息
    age_group           VARCHAR(16),              -- 年龄段: 18-25/26-35/36-45/46-55/56-65/65+
    gender              VARCHAR(8),
    source_province     VARCHAR(32),              -- 客源省份
    source_city         VARCHAR(32),              -- 客源城市
    travel_party_type   VARCHAR(16),              -- 家庭结构: SOLO/COUPLE/FAMILY/SENIOR/BUSINESS
    -- 行为
    total_voyages       INT,                      -- 累计航次数
    first_voyage_date   DATE,                     -- 首航日期
    last_voyage_date    DATE,                     -- 最近航次日期
    is_repeat           BOOLEAN,                  -- 是否回头客
    avg_repeat_interval INT,                      -- 平均复购间隔(天)
    -- 价值
    total_ticket_revenue DECIMAL(15,2),           -- 累计票务收入
    total_obr           DECIMAL(15,2),            -- 累计船上消费
    ltv                 DECIMAL(15,2),            -- LTV = ticket + OBR
    -- 会员
    loyalty_tier        VARCHAR(16),              -- 会员等级
    loyalty_join_date   DATE,                     -- 入会日期
    -- RFM
    rfm_recency_score   INT,                      -- R分(1-5)
    rfm_frequency_score INT,                      -- F分(1-5)
    rfm_monetary_score  INT,                      -- M分(1-5)
    rfm_segment         VARCHAR(32),              -- RFM分群名称
    -- 满意度
    latest_nps          INT,                      -- 最近NPS评分
    complaint_count     INT,                      -- 累计投诉次数
    -- 标签
    business_tags       VARCHAR(256),             -- 业务标签(JSON): 包船常客/MICE/高消费/...
    -- 元数据
    updated_at          TIMESTAMP,
    INDEX idx_rfm (rfm_segment),
    INDEX idx_source (source_province, source_city),
    INDEX idx_tier (loyalty_tier)
);
```
